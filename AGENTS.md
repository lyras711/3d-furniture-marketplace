# Project context

- Stack: React 19, TypeScript, Vite, React Three Fiber, Drei and Three.js. Use npm.
- `src/App.tsx` owns local editor state, history, catalogue UI, selection and shopping flow. `src/editor.ts` contains metric placement, opening attachment and validation. `src/SceneEnvironment.tsx` owns room rendering and pointer gestures.
- Room coordinates use metres with Y up; product and custom-item dimensions use centimetres. Rotation is radians around Y. Never scale catalogue dimensions to make products fit.
- This is a local-first editor with optional Firebase email/password accounts and cloud-saved projects. Local autosave and URL-fragment sharing remain available; Save also syncs to the signed-in user's profile. Purchase requests are stored for manual retailer availability checks and admin follow-up; no checkout, payment, retailer stock feed or automated order placement exists. Do not describe requests as completed purchases until an admin records manual fulfillment.
- Saved project key: `forma-room-planner-project`. Invalid data must not be silently overwritten; manual save preserves a recovery copy.

# Custom-space building (2026-09-14)

- New projects default to an empty 12 m build grid, no implicit walls, floor or furniture. Built-in living-room, bedroom and studio starters are opt-in.
- `schemaVersion: 3` uses explicit wall segments, per-object `inBasket`, catalog or custom room objects, and optional imported-plan provenance/room labels. Width/length describe the build grid, not the room. Closed planar wall loops determine floor polygons, including irregular outlines, shared-wall rooms and nested enclosures. Schema v2 and legacy catalog objects without basket state migrate with `inBasket: false`.
- Empty projects open in 2D wall mode. Walls snap to a 25 cm grid and nearby endpoints/segments; users can tap/click endpoints to chain segments or drag to draw, with live length and room-closure preview. Escape cancels the current chain; connected-corner edits update neighbours. Openings use `wallId` and `wallOffset` and follow their parent wall.
- Product movement uses 10 cm snapping when enabled. Full rotated footprints must fit a closed room and not cross a wall. Shift-click selects desktop groups; group drag/rotate/duplicate/delete preserves relative placement. Wall edits preserve furniture and show warnings rather than silently moving products. New and duplicated products start outside the basket; custom owner items never enter the basket. Only explicit catalog basket items appear in shopping-list totals, CSV and quote item lists.
- Mirror controls are limited to corner and modular sofas, where the catalog models support a useful left/right flip; general object scaling is not available.
- Legacy rectangles are migrated to four explicit boundary walls. Before v1 migration, the original JSON is retained under `forma-room-planner-project-before-custom-spaces`; before v2 basket migration it is retained under `forma-room-planner-project-before-explicit-basket`.
- Single-floor retail planner only: do not describe this as feature parity with the entire Sims game. Current build grid limit is 40 m; supported saved geometry is capped at 200 walls/openings.

# Deployment (2026-09-17)

- Catalog GLBs/thumbnails are uploaded to the `forma-furniture-marketplace.firebasestorage.app` bucket as public objects (`uploadFile` `{ public: true }` → `publicUrl()`); signed URLs are the fallback. The bucket CORS config allows GET/HEAD from `https://formivo3d.com`, the Firebase hosting domains and local dev ports — GLTFLoader fetches cross-origin and fails without it. If CORS changes, bump model URL query versions to bypass stale edge responses.
- `register-catalog` appends `?v=`/`&v=` content hashes without stripping existing query params, preserving signed URLs.
- `GOOGLE_APPLICATION_CREDENTIALS` points at a firebase-adminsdk key outside the repo. `.env.local` is only auto-loaded by `scripts/admin-server.ts`; CLI pipeline runs need the variable exported in the shell.
- `firebase.json` rewrites both `/api/admin/**` and `/api/worker/**` to Cloud Run `forma-admin-worker`. Cloud Tasks worker delivery requires WORKER_URL/WORKER_TASK_SECRET on the service; a failed enqueue falls back to in-process execution, which Cloud Run CPU throttling can still freeze after the response. A trailing newline in `WORKER_TASK_SECRET` silently 401s every delivery (HTTP headers strip it) — the env var is trimmed in `admin-server`, and the stored secret version must be clean.
- `ImportedProductModel` recolouring must preserve the mesh's material shape: assigning a material array to a single-material mesh (no geometry groups) makes Three.js draw nothing. Clone the scalar material for scalar sources, array for arrays.
- Scanning a product-page URL seeds that URL into discovery (`discoverProductUrls`); a bare domain scan still walks sitemaps/categories only.

# Drawing import (2026-09-22)

- The empty-state quick start exposes floor-plan import. `src/planImport.ts` provides an on-device axis-aligned filled-band fallback; it accepts PNG/JPG/WebP/SVG/PDF and analyzes only the first PDF page. Never generate a bounding rectangle as a fallback or infer metres from an unscaled raster.
- `scripts/plan-vision.ts` implements a replaceable `PlanVisionProvider`, currently backed by Vertex AI Gemini. `POST /api/planner/detect-floor-plan` requires a Firebase ID token, App Check token, and per-user daily quota. It accepts one plan image and one optional elevation image; image bytes are not stored by this service, only quota counters are persisted. The UI requires consent before sending either image, keeps local detection available, and shows confidence/approximation warnings. High-confidence vertical estimates can set ceiling, door and window heights; low-confidence or missing estimates use 2.8 m ceiling, 2.1 m doors, 1.35 m windows and 0.85 m sills. Local detection ignores elevations. Room photos and video are not supported.
- To enable remote AI: enable Firebase anonymous auth and web App Check, set the Vite Firebase values plus `VITE_FIREBASE_APPCHECK_SITE_KEY`, and grant the Cloud Run service account Vertex AI access. `PLAN_VISION_PROJECT`, `PLAN_VISION_LOCATION` (default `eu`), `PLAN_VISION_MODEL` (default `gemini-3.5-flash`), and `PLAN_DETECTION_DAILY_LIMIT` configure the provider. Local `npm run admin:server` needs Google ADC. Without these settings, the UI reports the AI failure and uses the local fallback when possible; do not claim remote AI is live until configured and tested.
- Scale calibration accepts one known distance between two selected image points or the full detected width. Detected/AI dimensions remain approximate; imported geometry stays editable. Wall features have optional `thickness` in metres (0.02–2); old projects default to 0.12 via `wallThickness`. Rendering, opening frames, skirting, window light offsets, furniture clearance and wall snapping use actual thickness; edits/history/save must preserve it.
- The fallback does not reliably recognize diagonal/outline-only walls or ambiguous symbols. Passing geometry tests does not establish accuracy on arbitrary drawings. Targeted checks: `npm test -- editor-model.spec.ts editor.spec.ts --grep "plan extraction|plan openings|wall thickness|floor-plan import"`.

# Touch gestures (2026-11-08)

- `src/gestures.ts` tracks active touch pointers with a window capture-phase `pointerdown` listener. It runs before OrbitControls' canvas listener, so a cancelled drag can re-enable the controls before the second finger reaches them. Do not move this tracking onto the canvas.
- Touch rules: tapping an unselected item selects it (`onClick`, `event.delta` ≤ 10 px); dragging an unselected item moves the camera. Only a selected item, door/window or wall handle drags, after a 6 px slop. A second finger cancels the drag and restores `dragSnapshot` (`cancelDrag`, no history entry). In the wall tool, a second finger drops the pending tap's corner. Mouse behaviour is unchanged: drags start immediately.
- OrbitControls `touches`: `ONE` pans in 2D with the Select tool, otherwise rotates (which does nothing while rotation is off). `TWO` is always dolly-pan.
- Double-tap/double-click on empty floor inside a closed room sets `addPoint` (ring marker) and opens Furnish. The next catalogue pick is placed at the nearest valid spot to that point. `addPoint` clears when the panel closes or the step changes. This is the one explicit-gesture exception to "steps never switch automatically".
- Tests: `gestures.spec.ts` (pure); in `editor.spec.ts`, `pinch()` uses CDP multi-touch. The "pinching on a selected item" test fails if multi-touch cancellation is removed.

# Doors and windows (2026-11-08)

- Placing a door or window (tool click, or "Add a door/window to this wall") selects it and returns to the Select tool. A second opening needs the tool again. This stops accidental extra openings when the user only wants to move the view.
- `RoomFeature` has optional `style` (door `hinged|double|sliding|opening`, window `casement|fixed|balcony`), `hinge` (`left` = wall-local −X end) and `swing` (`in` = into the room the wall bounds, decided by `wallInsideSign`; `in` when both or neither side is a room). Missing values mean hinged/casement, so there is no schema bump. `isProject` rejects a style for the wrong type and invalid hinge/swing values.
- `openingSizes` lists common sizes per style; the first entry is applied when switching style. New openings default to an 80×210 door and a 120×140 window with a 90 cm sill.
- `src/OpeningOptions.tsx` (inside `FeatureProperties`) shows type tiles (`radiogroup "Door type"/"Window type"`), "Common sizes", and for hinged/double doors "Door opens" (Into the room / Outward) and "Hinge on the other side". The numeric fields stay below under "Exact size".
- Rendering: `OpeningBody` in SceneEnvironment.
  - Plan view: swing arc and leaf follow hinge and swing; double doors get two arcs; sliding doors get two offset tracks; balcony doors a centre line.
  - 3D: one leaf, two leaves, or two offset sliding panels, or no leaf for an open doorway (an invisible plane keeps it clickable). Casement windows have a centre mullion, fixed windows none. Balcony doors are full height with no sill ledge.
- Door clearance (`placementWarnings`) uses a 65 cm passage on both sides, extended on the swing side to the leaf radius (hinged = width, double = width/2). Balcony doors get the passage only.

# Wall-mounted items (2026-11-08)

- `Product.mount: 'wall'` plus `mountHeight` (cm to the bottom edge), and `CustomRoomItem.kind: 'wall'`, mark wall items (`isWallMounted`). They store `wallId`, `wallOffset` (m from wall centre), `wallSide` (±1 along the wall normal) and `elevation` (m to the bottom). x/z/rotation are derived by `hangOnWall`: flush with the wall face, back at local −Z, rotation = wall rotation (+π on the −1 side). A plan-view tap on a wall's top falls back to the room side. Elevation is clamped below the wall top.
- `refreshOpenings` re-hangs wall items after wall edits. If their wall is deleted they stay put, detached (`wallId` cleared), and warn "no longer on a wall". `fitsFloor` only requires an existing wall. `overlaps` ignores wall items, so walkthrough collision and floor packing skip them. `rotateObjects` refuses them (Rotate button hidden).
- Warnings: overlapping a door/window on the same wall or another wall item on the same face, or a floor item tall enough to reach it ("may hit").
- Placement: on the selected/target wall, near a dropped or double-tapped point (within 1.6 m), or as a pending `hangItem` ("Tap/Click a wall to hang…"). Mobile shows a drawbar with Cancel; desktop shows a canvas tip, and Esc cancels. The mobile wall bar has "Hang something on this wall", which opens the Add sheet limited to Wall decor + Your own.
- Dragging slides along the item's own wall; in 3D it also moves up and down on the wall plane. Group drags leave wall items in place. Duplicate offsets along the wall. Details shows "Height above floor (cm)" instead of X/Z/Rotation.
- With "Lower front walls" on, wall items whose wall faces the camera are hidden, so they do not float. The render studio honours `elevation`.
- Five temporary sample items (`art-horizon`, `mirror-round`, `shelf-float`, `tv-wall-55`, `cabinet-upper`) follow the existing "Formivo sample / Formivo temporary / price null / illustrative dimensions" convention, with procedural geometry and SVG thumbnails. They are not retailer products. The catalogue now has 27 pieces (Kitchen 4).
